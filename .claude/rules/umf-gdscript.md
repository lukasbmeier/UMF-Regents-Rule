# GDScript, scenes and resources (client, sidecar, tests, tools)

- Strictly typed: every var, param and return; `:=` only when the right side is a constructor.
  The project treats warnings as errors.
- SDK questions: read the VENDORED SOURCE under `addons/SpacetimeDB/` (`spacetime.gd`, `core/`,
  `core_types/`, `nodes/`). There is no `docs/` folder in this copy; `docs/ARCHITECTURE.md` §SDK
  summarises it and the source is the tiebreaker. Never guess an API name: `# ASSUMPTION:` it.
- Only `foundation/net/spacetime_sync.gd` touches SDK types, the `SpacetimeDB` autoload or
  `spacetime_bindings/` (rule 3). Never mutate a row the SDK delivered (rule 6).
- `spacetime_bindings/` is generated (`tools/publish.sh --codegen`): never hand-edit it. Nor a baked
  `shared/content/*.json`, nor an `AnimationTree` (generated by `AnimationTreeBuilder`).

## Godot and the editor
- Prefer the headless test script to opening scenes.
- After editing a `.gd` with a `class_name`, re-import (`godot --headless --path . --import`) so
  `.godot/global_script_class_cache.cfg` updates; otherwise `class_name` lookups fail.
- "SpacetimeDB.Umf not found" in the editor: codegen has not run, or the alias differs from
  `NetConfig.module_alias`.
- If the editor disagrees with a headless run, the editor is stale (DECISIONS #46); autoload edits
  to `project.godot` need an editor restart.
- Rewriting a `@tool` script while its scene is open in Luke's editor can take the editor down
  (`docs/rules/held_items.md`, EDITOR PREVIEWS). An editor session of your own re-saves files: check
  the disk after it closes.
