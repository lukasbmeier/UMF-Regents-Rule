# AGENTS.md — operating rules for any AI agent working in this repo

Read this first, then `docs/ARCHITECTURE.md`, then the rules file for the system you are touching
(the index below). `docs/HANDBOOK.md` is the human guide; `docs/DECISIONS.md` says why things are
the way they are (indexed by system at its top).

## What this is
Universal Multiplayer Foundation: Godot 4.7 (strictly typed GDScript 2.0; 4.6 is the floor) client + SpacetimeDB 2.10 Rust module.
A genre-agnostic core (movement, sync, health, inventory, interaction) that genre layers build on.
Godot's high-level multiplayer is **not used**. SpacetimeDB is the authoritative state; Godot is a passive view with client-side prediction on top.

**The repo root IS the Godot project.** `project.godot`, `foundation/`, `tests/`, `addons/`, `sidecar/`, `game/`, `spacetime_bindings/` are all `res://`. `server/` (Rust) and `shared/` sit alongside them; `shared/` is reachable as `res://shared/`. Read any `client/...` path in an old note as root-relative.

## Built for designers (the owner's standing priority)
- This is a TEMPLATE: game designers, world designers and developers must be able to add and
  change things without editing the foundation or each other's work. Judge every change by that.
- Prefer what a designer can edit to a constant in code: data in `shared/*.json`, a `.tres` in
  the Inspector, a node placed in a scene, an editor preview. A genre never edits `foundation/`
  or `module.rs`; if it seems to need to, widen a hook (`docs/HANDBOOK.md` §11 lists the
  missing ones).
- The owner did not write this code and must be able to run it alone. `docs/HANDBOOK.md` is the
  human guide: a change to how something works, what it depends on, or what a change to it
  takes (restart, republish, codegen, regenerate) updates the handbook IN THE SAME CHANGE.

## Hard rules (violations fail review)
1. Strictly typed GDScript. Every var/param/return typed. `:=` only when the RHS is a constructor.
2. No `@rpc`, `MultiplayerSynchronizer`, `MultiplayerSpawner`, `ENetMultiplayerPeer`.
3. Only `foundation/net/spacetime_sync.gd` may reference SDK types, the `SpacetimeDB` autoload, or `spacetime_bindings/`. `tests/run_tests.sh` greps for this.
4. Components never own authoritative state. They receive it via `_on_row_updated(table, old, new)`. They may own `predicted` and presentation state only.
5. Components never reference UI. Low-frequency, `entity_id`-first events go on `SignalBus`. Position/velocity never go on `SignalBus`.
6. Rows delivered by the SDK are the cache's own `Resource` instances. **Never mutate one.** Copy values out (`MovementState.from_row`) or `duplicate()`.
7. Movement math: `Vector3` (f32) only in `movement_model.gd`; it is shared by client prediction and the sidecar. Every change ships regenerated GDScript golden vectors. The Rust `sim.rs` twin is frozen (Tier A idle only) — do not extend it. Rust⇄GDScript parity with `max_err = 0` applies to Challenge validators, the fight and the level bake.
7b. Authority logic (NPC brains, hit resolution, spawn/loot rules) lives ONLY under `sidecar/`, which is excluded from the client export. Nothing in `foundation/` or `game/` may reference `res://sidecar`. Lint-enforced.
8. Two-phase init: `_ready()` never touches synced data; `bind()` does.
9. Every table that describes an entity has `entity_id: u64` as PK and `world_id: u32`.
10. Tunables are data: movement in `shared/movement_config.json`, the foundation's rules (health, interact range, round plans, rate limits) in `shared/rules.json`, a genre's in `shared/<genre>/`. Never hand-edit a generated `.tres`/`.rs` copy.
11. Animation and VFX never produce gameplay events; they read state (`docs/ANIMATION_SPEC.md`). AnimationTrees are generated by `AnimationTreeBuilder`, never hand-authored.
12. One file per task. State assumptions inline as `# ASSUMPTION:` comments; do not silently guess API names.
13. Clients send inputs; servers derive outcomes. No reducer accepts a client-reported result. (Known exception still to fix: the kind-0 timing bar takes a stop position — `FOWL_PLAY_OPEN_ITEMS` A4.)
14. A player-callable reducer whose rows every client receives, or that moves a player between worlds, calls `spend_rate` first and has a line in `rules.json` `rate_limits` (DECISIONS #189). Dev helpers (`teleport`, `dev_nudge`) stay behind `require_dev_tools` (#187).
15. A table added → `tools/publish.sh --codegen` (the version check refuses every client otherwise, #164); a table reshaped → `--fresh` too, which wipes `umf`: the owner's say-so only.

## Verify loop
THE OWNER IS ON WINDOWS: give them `tools\publish.cmd` and `tools\run.cmd tests\<suite>.sh` (Git
Bash underneath; `tools/local.env` holds this machine's GODOT), never a bare `./x.sh`. Every server
suite publishes and wipes the TEST database `umf-test`, never `umf` (the owner's; a lint stops a
suite naming it). Never run two server suites at once: they share one database. Run the suites a
change touches, plus its negative; offer a full sweep before a commit. Why each layer exists:
`docs/rules/testing.md`.
```bash
cd server && cargo check --target wasm32-unknown-unknown   # the check that counts: module.rs is wasm-gated
cd server && cargo test                                    # golden, challenge, level, fishing, fight, rate, genres
GODOT=<path> ./tests/run_tests.sh          # lints + ~1500 headless unit/scene checks; fails on engine errors too
GODOT=<path> ./tools/publish.sh [--fresh] [--codegen]       # build, publish umf, regenerate bindings
GODOT=<path> ./tests/integration_test.sh   # every reducer and its refusals (the only coverage of module.rs)
GODOT=<path> ./tests/e2e_test.sh           # a real client against the real module: run before claiming anything works
GODOT=<path> ./tests/multiclient_test.sh   # two clients, distinct identities
GODOT=<path> LATENCIES="0 100 200" ./tests/playtest_test.sh   # movement feel through real keys
GODOT=<path> ./tests/remote_playtest.sh    # how a second client draws the first: smoothness, teleports, jumps
GODOT=<path> ./tests/fishing_playtest.sh   # the game played (SHOTS=<dir> photographs it: look at them)
GODOT=<path> ./tests/connect_playtest.sh   # the connect screen and Escape menu, fresh install
GODOT=<path> ./tests/sidecar_test.sh       # a real sidecar, with an unregistered control and a restart
GODOT=<path> ./tests/export_test.sh        # both presets exported, packs inspected, both builds run
GODOT=<path> ./tests/genres_test.sh        # the foundation built with no genres
GODOT=<path> ./tests/render_test.sh        # windowed: foliage, grass, lake, grip pictures, F11
```
Codegen by hand (publish.sh does this): `godot --headless --path . -s tools/codegen_config.gd`, `--import`, `--script res://addons/SpacetimeDB/cli.gd`, `--import` again (the second registers the generated `class_name`s). Smoke test against a live server: `godot --headless --path .` → `CONNECTED` → `local entity: N` → `world ready`.
Golden output must read `max_err=0.000e+00` on every case on both sides. A non-zero value under tolerance is a parity bug, not a pass — do not widen the tolerance.

## Using Godot MCP
- Prefer running the headless test script over opening scenes.
- After editing any `.gd` with `class_name`, re-import so `.godot/global_script_class_cache.cfg` updates; otherwise `class_name` lookups (and `SpaceTimeSync._find_global_class`) fail.
- If the editor reports "SpacetimeDB.Umf not found": codegen hasn't run, or the alias differs from `NetConfig.module_alias`.
- If the editor disagrees with a headless run, the editor is stale (DECISIONS #46); autoload edits to `project.godot` need an editor restart.
- Rewriting a `@tool` script while its scene is open in the owner's editor can take that editor down (`docs/rules/held_items.md`, EDITOR PREVIEWS).

## When you are unsure
- SDK behaviour → **read the vendored source** under `addons/SpacetimeDB/` (`spacetime.gd`, `core/`, `core_types/`, `nodes/`); this copy has no `docs/` folder. Key facts are summarised in `docs/ARCHITECTURE.md` §SDK — treat the vendored source as the tiebreaker.
- Rust module API → `docs.rs/spacetimedb/2.10.0`. Do not use 1.x spellings (`name =`, `ctx.sender` as a field, `ScheduleAt::Interval(...)`). `sim.rs` must never depend on the `spacetimedb` crate, and every table/reducer lives in `module/` behind `#[cfg(target_arch = "wasm32")]` (DECISIONS #27): violating either breaks `cargo test` at link.
- Design intent → `docs/ARCHITECTURE.md`, then `docs/DECISIONS.md`. If still unclear, leave an `# OPEN QUESTION:` comment and pick the option that keeps the genre layers thinner.
