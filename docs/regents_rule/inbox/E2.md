# E2: THE "BINDING AFTER 2.0S WITHOUT ROWS FOR SESSION_MEMBER" WARNINGS
Cause: `foundation/core/spacetime_entity.gd:332` (the bind timeout). The foundation's `SessionComponent`
(`foundation/components/session_component.gd:55-61`) REQUIRES `session_member` (only `lobby_member` is optional).
The foes (`game/regents/combat/foe.tscn`) and the guide (`guide.tres` -> `foundation/entities/player.tscn`) are built
on `player.tscn`, so they carry that component, but the server gives a member row only to a player joining a world's
session (`add_member`, `module/lifecycle.rs:254`). The ten: the guide (120) and the camp's nine foes (wolf x2, deer,
warrior x2, axeman, sparring skeleton, archer, imp). Players (kind 0) never warned. NOT ONLY NOISE: each of those NPCs
stays unbound, frozen at its first rows, for ~2.9 s after it comes into a client's ring (measured below), on every
ring change.
Built:
- `game/regents/npc_session_component.gd`: extends SessionComponent, `optional_tables()` = [session_member, lobby_member].
- `game/regents/combat/foe.tscn`: the inherited `Components/Session` node takes that script.
- `game/regents/npc.tscn` (new): player.tscn with the same override; `content/character/guide.tres` uses it (the scene
  is not in the bake: no re-bake, no publish).
- `game/regents/tests/bind_playtest.sh` + `tests/playtest/bind_playtest.{gd,tscn}`: one real client at 150 ms in the
  camp; times every entity from entering the tree to `bound`; fails a stall > 1 s or any "binding after" line, and
  names each warned entity's kind from the server.
How to play it: walk into the frontier camp: the foes and the Drillmaster move at once, not 2-3 s later.
Tested:
- bind_playtest.sh WITHOUT the fix (the negative): FAILED as it should: the ten above bound 2936-2978 ms after spawn,
  ten warnings; players 12-261 ms.
- bind_playtest.sh WITH the fix (2026-11-16, same run): PASSED, 3/0: the same ten bound 99-117 ms after spawn, no
  "binding after" line. (The first tries' "publish failed" was this change: `guide.tres` is a content source, so the
  build's stale-bake check refused it until re-baked; `shared/content/manifest.json`'s hash for it is the only change.)
- tests/run_tests.sh (after `git merge main`): 4610 passed, 0 failed, the lints, no unexpected engine errors.
- Not run: the integration suite (the master's), other playtests (no server change).
Needs on merge: none beyond the committed re-bake (the manifest hash; no table, no codegen, no publish needed for the play database: the client change is scenes only).
